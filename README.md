# 排阵 · 排球战术板

一款手机优先的中文排球接发战术板，采用已确认的 iOS 清爽浅色风格。纯静态 PWA，无第三方运行时依赖、账号、遥测或云端比赛数据库。

## 本地启动

需要 Python 3；测试与打包需要 Node.js 22 或更新版本。

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

访问 http://127.0.0.1:8765/ 。原三风格视觉样稿保留在 `/prototype/`，与正式版数据独立。

```sh
npm test
npm run build
```

构建结果为 `dist/`，可部署到支持 HTTPS 的静态网站平台。所有路径均为相对路径，兼容域名根目录或项目子目录。**手机不能使用电脑的 127.0.0.1 地址**；实际手机安装与离线使用需要部署后的 HTTPS 链接。本地 HTTP 局域网只能用来查看页面，无法完整验证 PWA。

## 比赛使用

1. 在“队员”编辑姓名与常规位置（主攻、副攻、二传、接应、自由人、其他），可以继续添加替补。初始七名队员按角色命名，建议赛前换成实际姓名。
2. “开始比赛 / 训练”选择队名、起始比分、轮次、首发及先发球方。支持不使用自由人，同一队员不能占多个首发角色。
3. 双方 `+1` 按每球得分制更新发球权。我方从接发转为发球时轮转一次，连续发球得分不轮转。
4. `−1` 仅修正分数，不回推发球方或轮次。误点请使用“撤销上次记分”同时恢复比分、轮次和发球方。
5. “校正比赛”可直接设置比分、轮次及发球方，并建立新的撤销起点。训练模式不自动结束比赛。
6. 六轮按钮用于查看其他轮次，预览期间加减分锁定，点击“返回当前轮”继续记分。
7. “调整站位”解锁拖动；点击“完成”保存并锁定，或“取消调整”恢复进入编辑前的站位。切换轮次或打开其他功能面板会保存并结束编辑。圆圈自动显示姓名最后一个字，也可用方向键微调。
8. “换人 / 换回”让替补继承原角色的六轮站位和轮转身份，记录本场换人，不改变比分。自由人可手动替换大主或大副，预设与实际比赛状态分开；发球方为我方时显示实际 1 号位队员，主图仅为接发预览。
9. “退出比赛”选择是否用本场六轮站位保存回当前阵容。临时换人不会保存为首发；关闭浏览器仅暂停，重开自动恢复比赛。

## 站位约定

R1：1 二传、2 大主、3 小副、4 接应、5 小主、6 大副；大主、大副贴二传，小主、小副贴接应。轮转方向为 `2→1→6→5→4→3→2`。

每轮初始都是规整的前三人、后三人，由用户自行拖动设计。图中前排 `4、3、2`，后排 `5、6、1` 分别以虚线连接。角色身份不会因拖动或跨越三米线改变。

按圆圈中心点严格检查：`x4<x3<x2`、`x5<x6<x1`、`y4<y5`、`y3<y6`、`y2<y1`。相等或颠倒显示红色提示，允许保留；没有黄色提示。该检查是战术示意，实际判罚以脚的位置和赛事规则为准。第一版不管理正式比赛的换人次数、资格、自由人发球或特定赛事试验规则。

## 保存、备份与离线

- IndexedDB 保存共用名单、多套首发与六轮站位及当前比赛；每次有效操作后保存。失败时会明确提示，可立即复制分享链接。
- “分享与备份”通过复制、粘贴分享链接保存或导入名单、首发和六轮阵型；仅在确认后替换本机配置，不包含比赛记录。
- 首次联网打开并显示“离线已就绪”后，应用资源会缓存。iPhone Safari 使用“分享 → 添加到主屏幕”安装。
- 不同浏览器、站点地址及主屏幕容器可能有不同数据；清理网站数据会移除本机记录。迁移到新地址请导出后再导入。
- 新版本等待用户主动更新，比赛中禁止刷新更新。代码资源变更发布时必须递增 `sw.js` 的缓存版本，保证离线资源为同一套版本。
- 数据只保存在本机，不上传到 GitHub 或托管服务。仓库和网站发布均不包含运行时队员数据。

## 项目结构

- `index.html`、`styles.css`、`app.js`：正式界面及交互。
- `core.js`：纯比赛、轮转、换人及备份校验逻辑。
- `storage.js`：IndexedDB 读写；`sw.js`、`manifest.webmanifest`、`icons/`：PWA。
- `tests/`：核心行为测试；`scripts/build.mjs`：静态打包。
- `prototype/`：已确认的视觉样稿与历史截图；`docs/`：验收记录。

浏览器验收记录见 [docs/acceptance.md](docs/acceptance.md)。iOS 27 真机安装和触摸操作仍需在实际手机上验收。

## 链接分享

在“分享与备份”中点击“分享队员与阵型”，复制链接发送给队友。可选择任意已保存阵容分享；比赛进行中可选择本场阵型及当前队员。分享包含全部队员、角色分配和六轮坐标，不包含比分、发球权、记分历史或换人记录。

接收方直接打开链接会显示导入预览，也可在“粘贴链接导入”中粘贴。确认导入后新增一套阵容，保留已有阵容；同名且同位置的队员复用，其余加入共用名单；当前比赛进行中时禁止导入，须先退出比赛。不提供 JSON 文件导出或上传恢复入口。

分享链接是固定快照，发送后继续改动不会同步更新，需要重新生成链接。数据经紧凑编码及浏览器原生 deflate 压缩存入 URL 片段，完整链接不依赖云端名单存储；在线生成短链接时，原链接（包含名单及阵型）会交给 da.gd 保存映射。拿到完整链接的人可以导入名单。缺少压缩 API 时生成明文编码链接；无法解压的旧浏览器提示更新。链接最多 16000 字符，解码上限 64KiB；超长名单需要缩短姓名或减少替补后重新生成。

`sharing.js` 管理分享格式、压缩、校验及导入；`tests/sharing.test.js` 覆盖分享流程。既有本机数据及已生成的分享链接保持兼容。

## 队员字段简化

队员编辑仅填写姓名与具体位置，不再提供简称输入。圆圈自动使用姓名最后一个字。位置支持二传、大主、小主、大副、小副、接应、自由人及其他；上方首发分配仍独立管理实际轮转角色。旧数据中的主攻、副攻按已有首发角色识别大小，未分配角色的旧替补需自行选择具体位置。分享数据升级为 v2，继续接收旧 v1 分享链接；旧客户端收到新链接时会提示更新应用。

- 手机单列布局，浅灰背景、白色比分板、浅蓝灰球场；仅前后排队员使用蓝紫区分。

### 队员位置与首发角色分开

队员列表只填写常规位置，主攻、副攻均不区分大小。上方首发角色继续区分大主、小主、大副、小副，决定轮转角色；球场显示保持不变。旧数据与旧分享链接中的大小主副位置会合并为主攻、副攻，角色分配与站位不变。

### 主屏幕图标

主屏幕及网站图标统一为深色底白色“阵”字，与界面品牌一致。提供 180px Apple Touch Icon、192px 与 512px PWA 图标。若已安装旧图标，更新网站后重新添加到主屏幕以刷新 iOS 保存的图标。

当前 Sites 域名在部分网络下不可直连；网页 App 安装与离线缓存无法解决首次访问域名的网络限制。可将 `dist/` 内文件原样部署到其他支持 HTTPS 的静态托管。更换地址前先复制队员与阵型分享链接，新地址上粘贴导入，比分记录不包含在分享中。

## 短链接与自由人（2026-10-21）

分享优先使用 da.gd 生成短链接；粘贴短链接可展开并预览导入。在线服务不可用时，可复制完整链接；完整链接离线生成，短链接生成及展开需要联网。分享快照 v3 增加自由人替换角色和每轮接发预设，继续接收 v1/v2 链接；旧客户端需更新才能导入 v3。

队员面板默认勾选“大主、大副”，小副不被替换。赛前每轮可选择接发预览的自由人状态；开场设置决定本场实际状态。比赛中“自由人”按钮独立处理换入和原队员换回，不属于普通换人。当前轮次显示实际状态，其他轮次仅为接发预览。

依据 FIVB 2025–2028 第 19.3 条，应用检查后排身份、单自由人、禁止替换发球队员、原队员换回及两次替换之间完成一球；轮转进入前排或成为发球队员时自动显示原队员换回并记录。只有 ＋1 作为完成一球，−1 不推进回合。手动替换后不能用记分撤销越过该操作，可用“校正比赛”核对现场状态并重建记分起点。旧版进行中的比赛需先确认实际自由人状态。

本版本只支持一名指定自由人。裁判授权、死球、发球哨及替换区由使用者现场确认；伤病重新指定、判罚等例外需按裁判决定使用校正，不自动裁定。官方规则：<https://www.fivb.com/wp-content/uploads/2025/01/FIVB-Volleyball_Rules2025_2028-EN-v05.pdf>。


## 多套阵容（2026-10-21）

顶部选择阵容，“管理阵容”可重命名、复制、新建规整阵容及移除当前阵容（至少保留一套，最多 30 套）。队员姓名及位置共用，每套阵容独立保存七个首发角色、六轮站位和自由人替换角色／预设。编辑后自动保存，切换和重开页面均保留。旧版配置迁移为“阵容 1”，已有比赛继续保留。

比赛中锁定阵容选择及管理，普通换人只影响本场。退出时可将站位保存回开场使用的阵容，其他阵容不受影响。被任意阵容或比赛记录引用的队员不能移除；姓名／位置修改会反映到所有阵容。

分享格式 v4 携带所选阵容的名称、首发、六轮站位、自由人设置和共用名单，仍接收 v1–v3 链接。导入新增并切换到该阵容，不覆盖已有阵容；精确同名同位置的唯一队员复用，重名歧义不自动合并。旧客户端接收 v4 链接需更新应用。


## Safari 更新修复（2026-10-21.3）

旧版缓存优先策略不会因为普通刷新或首页加查询参数而跳过缓存。若看不到更新入口，用 Safari 在同一域名打开 `update.html`，点击“检查并更新应用”，完成后“打开排阵”。更新页不读写 IndexedDB，不注销服务工作线程，不清除网站数据；Safari 与已安装主屏幕 App 若使用独立存储容器，需在实际使用的容器中更新。

新版注册设置 `updateViaCache: none`；启动、返回前台、联网和打开帮助时主动检查（自动检查间隔至少一分钟），帮助面板始终提供手动检查。待更新状态优先于离线就绪状态显示；用户点击启用且没有比赛时才刷新。安装新资源时使用 reload 请求，整套缓存下载成功后再激活。更新流程的自动化测试覆盖安装、失败、超时和激活顺序；未连接真实 iPhone，需用户确认手机端最终结果。
